# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: [tests_load.md](../../practice_01/tests_load.md)
- Что хотим улучшить: добавить сценарии, численные пороги и связь с метриками из [problem.md](../../practice_01/problem.md); сохранить существующую структуру без новых разделов

## Примеры

### Хороший результат

"Добавь три воспроизводимых сценария нагрузки с p95, error rate и timeout rate; методику замера отрази в тех же колонках таблицы без новых разделов: в 'Нагрузка и длительность' укажи прогрев и основную фазу, в 'Что измеряем' перечисли метрики и как их считать, в 'Подтверждение' укажи инструмент (k6/Locust) и артефакт отчёта. Свяжи пороги с целями из problem.md (ускорение и стабильность). Формат — таблица с существующими колонками и числовыми порогами (мс, %)."

### Плохой результат

"Сделайте нагрузочное тестирование получше. Время ответа должно быть быстрым, ошибок быть не должно."

## Запрос

Подготовь few-shot обновление для tests_load.md на основе Хорошего примера: предложи 3 сценария нагрузки (Smoke/Stress/Soak) и заполни существующую таблицу колонками: Сценарий; Нагрузка и длительность (укажи прогрев и основную фазу); Допустимый предел (числа: p95 в мс, error rate %, timeout rate %); Что измеряем (p95 по основной фазе, error/timeout определения); Подтверждение (инструмент замера, артефакт отчёта). Новых разделов не добавляй — всю методику скомпонуй в эти поля. Свяжи пороги с целями из practices/practice_01/problem.md (ускорение первичного ревью, воспроизводимость). Язык — русский, формат — Markdown-таблица, без общих слов.

## Что получили

Результат: сформированы 3 сценария —
- Smoke: 1 RPS; прогрев 30 с, основная фаза 1 мин; p95 < 800 мс, error rate < 1%, timeout rate < 1%; измеряем p95 по основной фазе; подтверждение — отчёт k6/эквивалента.
- Stress: ступенчатый рост 1→5 RPS, шаг 1 RPS каждые 30 с до 5 мин; p95 < 1500 мс, error rate < 2%, timeout rate < 1%; измеряем p95 по основной фазе на пике; подтверждение — отчёт k6.
- Soak: 2 RPS в течение 10 мин; p95 < 1200 мс, error rate < 1%, timeout rate < 1%; измеряем p95 по основной фазе; подтверждение — отчёт k6.
Методика не вынесена отдельным разделом — она скомпонована в поля "Нагрузка и длительность", "Что измеряем" и "Подтверждение".
