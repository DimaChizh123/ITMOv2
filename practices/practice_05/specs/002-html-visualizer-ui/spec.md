# Feature Specification: HTML Visualizer UI (Sudoku Hint + Pattern Card)

**Feature Branch**: `[002-html-visualizer-ui]`

**Created**: 2026-11-02

**Status**: Draft

**Input**: User description: "Мы делаем генератор самодостаточной HTML-страницы для визуализации подсказки судоку и карточки теории паттерна. Спека для UI: макет, состояния, входные данные." (Синхронизировано с specs/contract.md)

## User Scenarios & Testing (mandatory)

### User Story 1 - Просмотр подсказки (Placement/Elimination) (Priority: P1)

Пользователь открывает самодостаточную HTML-страницу, видит исходную сетку судоку 9×9 с координатами и карандашными кандидатами. Подсветка показывает опорные клетки паттерна, целевую клетку ответа или кандидаты на удаление, а в боковой панели — краткую справку по паттерну и как его распознать.

**Why this priority**: Это основной сценарий, ради которого создаётся визуализатор.

**Independent Test**: Открыть страницу в браузере с входными данными, где присутствует либо placement, либо eliminations. Проверить: наличие координатных подписей r1..r9, c1..c9 (производные от 0-based входа), толстых границ 3×3, подсветок (синий для базовых ролей, жёлтый для pincer, зелёный для ответа, красные зачёркнутые бейджи на кандидатах).

**Acceptance Scenarios**:

1. Given валидная сетка и hint с placement, When страница сгенерирована, Then видна зелёная подсветка клетки ответа и цифра размещения в этой клетке.
2. Given валидная сетка и hint с eliminations, When страница сгенерирована, Then в соответствующих клетках видны красные зачёркнутые бейджи на указанной цифре-кандидате.
3. Given есть anchors у паттерна, When страница сгенерирована, Then опорные клетки подсвечены акцентами (синий/жёлтый) согласно их ролям.

---

### User Story 2 - Нет подсказок (none) (Priority: P1)

Пользователь открывает страницу и получает сообщение, что подсказок не найдено, при этом сетка и кандидаты отображаются без акцентных подсветок; боковая панель показывает область справки с идентификатором паттерна и пояснением, что подсказок нет.

**Why this priority**: Должна быть понятная обратная связь при отсутствии результата.

**Independent Test**: Открыть страницу со статусом `none`. Проверить: баннер/индикатор отсутствия подсказок, отсутствие зелёной/красной подсветки и зачёркиваний, видимость сетки и кандидатов, корректная панель справки.

**Acceptance Scenarios**:

1. Given валидная сетка и статус none, When страница загружена, Then показывается уведомление «Подсказок не найдено» и нет целевых подсветок.

---

### User Story 3 - Ошибка валидации/противоречия (Priority: P1)

Пользователь открывает страницу с ошибкой входных данных (например, противоречия в строках/столбцах/блоках). Он видит наглядный баннер ошибки, сетка может быть скрыта или отображаться в неактивном виде.

**Why this priority**: Строгая проверка входа — ключевое требование; ошибка должна быть ясной.

**Independent Test**: Открыть страницу с JSON `{ok:false, error:"..."}`. Проверить: видимость баннера ошибки, текст причины, отсутствие подсветок. Если вход содержит `visual:true` и предоставлен `grid`, страница также отображает сетку (без подсказок).

**Acceptance Scenarios**:

1. Given некорректный `grid`, When страница открыта, Then отображается красный баннер ошибки с сообщением и без подсказочных акцентов.

---

### User Story 4 - Адаптивный просмотр (Priority: P2)

Пользователь открывает страницу на ноутбуке и телефоне. Разметка корректно укладывается: поле остаётся квадратным и читабельным, панель справки доступна ниже или сбоку.

**Why this priority**: Практичность рендера в разных окнах/устройствах.

**Independent Test**: Изменять ширину окна. Проверить: сетка не «ломается», подписи координат остаются читаемыми, панель справки перестраивается под мобильный вид.

**Acceptance Scenarios**:

1. Given ширина < 640px, When страница сжата, Then панель справки уходит под сетку, контент остаётся читаемым.
2. Given ширина ≥ 640px, When страница открыта на десктопе, Then панель справки располагается справа от сетки.

---

### Edge Cases

- Отсутствуют кандидаты для части пустых клеток: клетка отображает пустую 3×3 сетку без цифр.
- Имеется и placement, и eliminations: приоритет визуализации обоих; зелёная подсветка клетки ответа + красные зачёркивания кандидатов.
- Несколько опорных групп паттерна: роли различаются по цветам; если ролей больше двух, вторичные отображаются нейтральным акцентом.
- Очень длинные тексты в панели справки: текст переносится, вертикальная прокрутка внутри панели допускается.
- Несоответствие индексации (0-based vs 1-based) во входных данных: входные координаты строго 0-based (0..8); UI конвертирует подписи в r1..r9, c1..c9 на рендере. При нарушении формата — состояние Error.

## Requirements (mandatory)

### Functional Requirements

- FR-001: Визуализатор должен генерировать один самодостаточный HTML-файл со встроенными стилями (inline CSS); без внешних JS/CSS библиотек.
- FR-002: Разметка игрового поля выполнена на CSS Grid: 9×9 клетки, с утолщёнными границами блоков 3×3.
- FR-003: По горизонтали поверх сетки отображаются подписи столбцов `c1..c9`, по вертикали слева — подписи строк `r1..r9`.
- FR-004: Заполненные цифры отображаются крупным кеглем, центрированы в клетке.
- FR-005: Пустые клетки содержат внутреннюю мини-сетку 3×3 для карандашных кандидатов. Каждый кандидат — малый номер в соответствующей позиции.
- FR-006: Подсветки и роли anchors (сопоставление с контрактом):
  - Опорные клетки паттерна: маппинг семантических ролей из логики → цветовой акцент.
    - primary (синий): pivot, target, pair, corner, box_candidate, line_candidate, row_candidate, col_candidate.
    - secondary (жёлтый): pincer.
  - Верный ответ (placement): зелёная подложка/рамка клетки; цифра ответа видима. Поле данных: `action.placement.value` (UI может отображать как digit).
  - Кандидаты на удаление (eliminations): красный зачёркнутый бейдж поверх/вместо малого номера кандидата внутри клетки. Поле данных: `action.eliminations[].remove` (UI может отображать как digit).
- FR-007: Боковая панель «Справка по паттерну» содержит: название, сложность (difficulty), простое объяснение сути (summary), как найти глазами (intuition/spotting), как применить (how_to_apply:list[string], рендер как список). При отсутствии части полей показывать заглушки «—». Если `how_to_apply` придёт одной строкой, UI приводит к массиву из одной строки.
- FR-008: Состояние `none` «Подсказок не найдено» — информативное сообщение без зелёных/красных акцентов; сетка и кандидаты остаются видимыми.
- FR-009: Ошибка входных данных — заметный красный баннер с текстом ошибки; подсказочные акценты скрываются.
- FR-010: Адаптивность: при ширине ≥ 640px сетка слева, справка справа; при ширине < 640px — справка под сеткой; поле всегда сохраняет соотношение 1:1.
- FR-011: Индексация входных координат — строго 0-based (rows 0–8, cols 0–8) в данных. Подписи r1..r9 и c1..c9 формируются на рендере.
- FR-012: Не выполнять вычислительную логику судоку; визуализатор только отображает предоставленные данные (включая кандидаты). Валидация только формальная (формат/диапазоны).
- FR-013: Доступность: контрасты цветов достаточные; для акцентов применяются иконки/рамки, чтобы различались не только по цвету. Предусмотреть текстовые подсказки (title/aria-label) на ключевых элементах.
- FR-014: Переиспользование: один и тот же компонент рендера поля 9×9 (с кандидатами и подсветками) используется и для основного поля, и для отрисовки `card.example` в боковой панели «Наглядный пример техники».

### Key Entities

- VisualGrid: описание 9×9 поля, координат и границ 3×3.
- Cell: единичная клетка с `value` и `candidates[1..9]`.
- HintHighlight: подсветки по ролям: `anchors` (семантические роли из логики), `placement` (value), `eliminations` (remove).
- PatternCard: данные справки: `title`, `difficulty`, `summary`, `intuition`, `how_to_apply`.
- ErrorBanner: вид и текст ошибки.

## Success Criteria (mandatory)

### Measurable Outcomes

- SC-001: В 100% тестовых входов с валидным `grid` корректно рисуются толстые границы 3×3 и подписи r1..r9, c1..c9.
- SC-002: При наличии `placement` пользователь однозначно видит клетку ответа в зелёной подсветке и верную цифру (value отображается как digit).
- SC-3: При наличии `eliminations` зачёркнутые красные бейджи соответствуют всем указанным кандидатам и только им (remove отображается как digit).
- SC-004: На экранах шириной 360–1440px макет не ломается; панель справки корректно перестраивается.
- SC-005: При ошибочном входе отображается баннер ошибки с исходным сообщением; подсветки отсутствуют.

## Assumptions

- Генератор формирует статический HTML с inline CSS, без JS. Интерактивность вне объёма v1.
- Кандидаты передаются внешней логикой; UI их не вычисляет.
- Цветовые токены: primary (синий), secondary (жёлтый), success (зелёный), danger (красный), нейтральные серые для сетки.
- Шрифты системные (sans-serif); отсутствие кастомных веб-шрифтов.

## Page Layout (HTML + CSS Grid)

Описание визуальной структуры (без кода):

- Общий контейнер: CSS Grid с двумя областями на десктопе: `board` и `sidebar` (2 колонки: авто для поля, 320–400px для панели). На мобильном — одна колонка, `sidebar` под `board`.
- Поле 9×9:
  - Grid 9×9, каждая клетка — квадратный элемент. Толстые границы между блоками 3×3 (после строк 3 и 6; столбцов 3 и 6).
- Верхняя линейка над первой строкой: `c1..c9` (центрированы над столбцами). Формируются на основе 0-based индексов столбцов (c = index+1).
  - Левая линейка слева от каждой строки: `r1..r9` (центрированы по высоте строки). Формируются на основе 0-based индексов строк (r = index+1).
  - Заполненные клетки: крупная цифра, полужирная.
  - Пустые клетки: внутренний мини-grid 3×3 для кандидатов 1..9 (позиции: 1 в левом-верхнем, 9 в правом-нижнем). Отсутствующие кандидаты не рисуются.
  - Подсветки:
    - Anchors: рамка 2px и лёгкая подложка (primary=синий, secondary=жёлтый). Если больше 2 ролей — tertiary=светло-серый акцент.
    - Placement: зелёная рамка 3px и мягкая подсветка фона клетки.
    - Eliminations: для соответствующих кандидат-цифр малый бейдж (кружок/капсула) красного цвета с line-through на цифре; при отсутствии кандидата показывать маленький красный зачёркнутый бейдж с цифрой в углу клетки (правый-верхний) как сигнал «удаление». Источник цифры — поле remove.
  - Тултипы/aria: у клетки title с координатами (например, "r3c5"). У подсветок — role-метки ("anchor: primary", "elimination: 7").
- Боковая панель «Справка по паттерну»:
  - Заголовок: `pattern.title` и чип сложности `pattern.difficulty`.
  - Блоки текста: краткая суть (summary), как узнать глазами (intuition/spotting), как применить (how_to_apply — список пунктов).
  - Наглядный пример техники (card.example): отдельный подблок с миниатюрным рендером 9×9, реализованный тем же компонентом рендера, что и основное поле. Включает anchors/action из example согласно контракту.
  - При статусе `none`: заголовок включает идентификатор типа паттерна/поиска, текст о том, что на текущей позиции подсказка не найдена.
  - Прокрутка внутри панели при переполнении.

## Screen States

1. Success: placement
- Зелёный акцент на клетке `{row, col}` (0-based), цифра `value` отображается крупно (как digit).
   - Если есть eliminations одновременно — показывать оба вида акцентов.

2. Success: elimination(s)
- В каждой паре `{row, col, remove}` кандидат `remove` в мини-сетке зачеркивается с красным бейджем. Если кандидат не был в списке кандидатов — отрисовать маленький красный бейдж с цифрой в правом-верхнем углу клетки.

3. None (no hints)
   - Видимое сообщение «Подсказок не найдено». Подсветки anchor/placement/eliminations не показываются.

4. Error (invalid/contradiction)
- Широкий красный баннер с текстом `error` сверху страницы (формат ошибки: `{ok:false, error:string}`). При наличии визуального режима и предоставленного `grid` — сетка отображается без подсказок.

## Expected Input Data (JSON structure) — согласно specs/contract.md

UI-генератор ожидает объект результата логики. Валидация строгая. Координаты в данных — 0-based (0..8); подписи r1..r9/c1..c9 формируются на рендере.

Успешный ответ:

```
{
  "ok": true,
  "result": {
    "type": string,               // идентификатор техники
    "visual": {
      "grid": number[9][9],
      "candidates": number[][9][9],
      "pattern": {
        "id": string,
        "anchors": [{"row":0..8, "col":0..8, "role": string}],
        "params": object | null
      } | null,
      "action": {
        "type": "placement" | "elimination",
        "placement"?: {"row":0..8, "col":0..8, "value":1..9},
        "eliminations"?: [{"row":0..8, "col":0..8, "remove":1..9}]
      } | null
    },
    "card": {
      "title": string,
      "difficulty": string,
      "summary": string,
      "intuition": string,
      "how_to_apply": string[],
      "example"?: {
        "grid": number[9][9],
        "candidates": number[][9][9],
        "pattern": {
          "id": string,
          "anchors": [{"row":0..8, "col":0..8, "role": string}],
          "params": object | null
        } | null,
        "action": {
          "type": "placement" | "elimination",
          "placement"?: {"row":0..8, "col":0..8, "value":1..9},
          "eliminations"?: [{"row":0..8, "col":0..8, "remove":1..9}]
        } | null
      } | null
    } | null
  }
}
```

Ошибка:

```
{
  "ok": false,
  "error": string
}
```

Правила интерпретации:

- `grid[r][c] = d` при d∈1..9 — заполненная цифра; при d=0 — пустая клетка.
- `candidates[r][c]` — массив уникальных цифр 1..9; порядок не важен.
- Роли anchors маппятся на цвета: primary (синий) для pivot/target/pair/corner/box_candidate/line_candidate/row_candidate/col_candidate; secondary (жёлтый) для pincer.
- Поля `value`/`remove` UI отображает как digit на рендере, не изменяя контракт.
- `card.example` визуализируется тем же компонентом 9×9, что и основное поле.

### Mapping from MCP outputs (informative)

- `result.visual.action.placement.value` соответствует `sudoku.hint.placement.value`.
- `result.visual.action.eliminations[].remove` соответствует `sudoku.hint.eliminations[].remove`.
- `result.visual.pattern.anchors[].role` соответствует семантическим ролям из логики; UI делает цветовой маппинг.
- `result.card` — из PATTERN_CARDS по `result.type` плюс example в унифицированном формате.

## Validation Rules (UI input)

- `ok` обязателен. При `ok:false` должен быть `error` (string).
- Размеры `grid` и `candidates` строго 9×9, значения в допустимых диапазонах.
- Координаты `row/col` строго 0..8.
- При `action.type = placement` поле `placement` обязательно; при `action.type = elimination` — `eliminations` не пустой.
- При наличии `card.example` структура соответствует визуальному формату.

## Non-Goals

- Вычисление кандидатов или решение судоку — вне объёма UI.
- Генерация нескольких страниц или bundled-ассетов — только одна самодостаточная HTML-страница.
