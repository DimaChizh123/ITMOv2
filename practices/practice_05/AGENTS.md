# Правила работы агента в этом проекте

- Следовать строгим проверкам на валидность входных данных. В случае сомнений — возвращать понятные ошибки и не пытаться «чинить» вход молча.
- Для задач судоку использовать MCP tool `sudoku` и его tool `sudoku.hint` вместо самостоятельного анализа. Агенты не решают судоку сами, а вызывают tool.
- После правок в коде вызывать автопроверку (скрипт `scripts/verify.py`) — это делает плагин автоматически; агент должен учитывать её вывод при принятии решений.
- Придерживаться минимальных правок: вносить самые маленькие корректные изменения и пояснять неочевидные места короткими комментариями.

## MCP sudoku tool

- Расположение: `practices/practice_05/mcp/sudoku/index.py`
- Запускать через `python3`, передавая JSON на stdin. Поле `tool` должно быть `"sudoku.hint"`, поле `args.grid` — валидная 9×9 матрица чисел 0–9.
- Пример запуска:

```
python3 practices/practice_05/mcp/sudoku/index.py << 'EOF'
{"tool":"sudoku.hint","args":{"grid":[[4,0,0,0,5,0,0,0,0],[5,0,1,0,8,0,0,0,0],[0,0,0,7,9,6,0,0,0],[0,0,7,0,0,0,0,0,0],[0,0,9,0,0,8,6,0,0],[0,5,0,0,0,0,9,0,7],[0,0,0,0,0,3,0,0,5],[0,0,0,6,0,0,0,8,0],[2,3,0,0,0,0,0,1,0]],"verbose":true}}
EOF
```

- Поиск/нахождение tool:
  - Предпочитать `grep` по содержимому (`sudoku\.hint`) вместо glob по именам файлов. Файл называется `index.py` и лежит в каталоге `mcp/sudoku/`.
  - При отсутствии алиаса `python` использовать `python3`.

Примечание: входные данные проверяются строго. В случае некорректного `grid` (`не 9×9`, не числа 0–9, противоречия в строках/столбцах/блоках) tool вернёт понятную ошибку. 

### Объяснения и формат ответа
- Для объяснений/теории вызывать MCP `sudoku.patterns` с `args.pattern`, равным `result.type` из `sudoku.hint`. Если `sudoku.patterns` недоступен, давать краткое описание простыми словами и указывать идентификатор техники; не выполнять логические шаги на сетке.
- Формат ответа: тип техники, краткое человеческое пояснение (summary/intuition), шаги (3–5), затем структурированные данные из MCP. По умолчанию verbose включён; отключать только по явной просьбе.
- При некорректном входе (не 9×9, не 0–9, противоречия) возвращать сообщение MCP без «починки» и просить предоставить валидную сетку.

### Различие структур данных `sudoku.hint` и `sudoku.patterns`
- `sudoku.hint` — оперативная подсказка по текущей сетке; может содержать `placement` или `eliminations` с элементами вида `{row, col, remove}`.
- `sudoku.patterns` — справочная карточка техники: `title`, `summary`, `intuition`, `how_to_apply`, `example`, `highlights`. В `highlights.eliminations` используется поле `digit` для демонстрации, не для применения к сетке.
- Эти структуры предназначены для разных целей; поля не смешивать (`remove` vs `digit`).
