## Context Pack для первого рабочего сценария

### Факты и правила

- Вход: один diff PR (в обучающем запуске — файл TRAINING_PR.diff).
- Задача помощника на один PR: 1) краткое описание изменения; 2) не больше трёх рисков с файлом, строкой и доказательством; 3) список проверок, которые стоит запустить.
- Решение всегда принимает человек. Помощник не может approve, merge или менять код.
- Тестовый запуск выполняется без инструментов и без автоматического контекста репозитория.
- Используемая модель для экспериментов: vsellm/openai/gpt-5.
 - Формат ссылок на строки: file:line, для блоков — file:start-end.

### Формат входа и результата

- Вход: текстовый diff одного PR.
- Результат: структура из трёх разделов.
  - Краткое описание изменения (1–3 предложения).
  - Риски: не более 3. Каждый риск обязан содержать: файл, строку(и) и доказательство (подтверждение по diff и/или воспроизводимая проверка).
  - Проверки: перечень воспроизводимых проверок/шагов, которые стоит запустить.
  - Ограничение объёма: общий ответ до 300 слов, приоритет — соблюдение структуры.

### Ограничения и запрещённые действия

- Нельзя approve, merge или менять код.
- Нельзя ссылаться на внешние источники, кроме переданного diff.
- Нельзя выдавать предположения как требования; неизвестное отмечать вопросами.
- В тестовом процессе запрещено использование инструментов.

### Хороший пример

```text
app/api.py, create_review — обращение payload["diff"] вызывает KeyError,
если в теле запроса нет поля diff. Проверка: отправить POST /api/reviews
с пустым JSON-объектом и проверить ответ сервиса.
```

### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

### Что пока неизвестно

- Где именно сегодня возникают основные задержки или типовые ошибки в процессе ревью (стадия, причины, частота). [Обновлено: задержки — поиск рисков и формулировка проверок]
- Требуемая точность и формат ссылок на строки при сложных изменениях (удаления/перемещения).
- Ограничения по объёму ответа (жёсткий лимит символов/строк для разделов).
