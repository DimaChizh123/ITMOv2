# Анализ процесса: AS IS и TO BE

Файл ведёт OpenCode. Обсудите с агентом содержание и проверьте предложенный diff. Все дополнения и исправления поручайте агенту в чате.

## AS IS

Участники: ревьюер PR, рабочий агент OpenCode (для эксперимента), тестируемая модель.

Текущий процесс ревью diff без структурированного помощника:
- Ревьюер открывает PR и читает diff.
- Самостоятельно формулирует риски, пытается сослаться на файл/строки и придумать проверки.
- Задержки: поиск существенных рисков в больших diff и формулировка воспроизводимых проверок.
- Потери: часть выводов не подтверждается diff, проверочные шаги не фиксируются, что ухудшает воспроизводимость.


## TO BE

Процесс с AI‑помощником по согласованному Master Prompt v1.

```mermaid
flowchart LR
    A[PR открыт: доступен diff] --> B[AI формирует Summary]
    B --> C[AI выделяет ≤3 риска с file:line/start-end]
    C --> D[AI предлагает Checks (воспроизводимые шаги)]
    D --> E{Достаточно подтверждений?}
    E -- Да --> F[Ревьюер проверяет и комментирует]
    E -- Нет --> G[Ревьюер задаёт вопросы/уточняет]
    F --> H[Проверяемый результат: комментарии с доказательствами]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Формат результата | Неформализован | Summary, ≤3 риска, Checks | Проверка структуры ответа P1-02 |
| Подтверждения | Могут отсутствовать | Каждый риск с file:line/start-end или проверкой | Содержимое P1-02, ручная верификация по diff |
| Время первичного ревью | Дольше | Сокращается | Метрика времени по 10 PR до/после |
| Воспроизводимость | Низкая | Выше за счёт Checks | Доля комментариев с проверками |

## Как использовали AI

- Для чего: описать процесс до/после и зафиксировать проверяемые изменения.
- Тип промпта: master prompt для запуска P1-02.
- Строка в [`prompts.md`](prompts.md): [P1-02](prompts.md#журнал-запросов-и-проверок).
- Что проверил студент и какие исправления поручил агенту: сопоставлена диаграмма со структурой Master Prompt; добавлены узлы для ссылок на строки и Checks.
