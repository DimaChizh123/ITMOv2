# Отчёт 2. Повторные атаки после исправлений

Изменения в коде и результаты повторных атак.

Исправления:

1. Принудительная авторизация для чувствительных эндпоинтов, отказ от доверия заголовку `X-Role`: сервер использует токен, чтобы определить `id` и `role`.
2. Параметризованные запросы вместо f-string для `GET /profile`, `GET /search`, ограничение `GET /orders` владельцем (или staff).
3. `GET /files` возвращает только собственный чек пользователя, игнорируя параметры.
4. `GET /debug/logs` доступен только сотруднику.
5. Экранирование HTML в `/reviews/view` для защиты от XSS.
6. `POST /orders` игнорирует цену клиента и использует цену каталога.
7. Ограничения инструментов помощника: чтение только собственного чека; экспорт профилей только для staff; удаление только своей директории `files/<user>`.

Повторные испытания:

1. SQL-инъекция: невозможно — запросы параметризованы, а `/profile` игнорирует `id` в query.
2. Подмена роли: невозможно — роль берётся из сессии.
3. Чтение чужих/приватных файлов: невозможно — `/files` и инструмент `read_file` ограничены.
4. XSS: HTML экранируется; вставка `<script>` отображается как текст.
5. Инструменты: удаление корня песочницы и экспорт профилей клиентом запрещены, чтение чужого файла запрещено.
6. Манипуляция ценой: цена строго из каталога.
7. Логи: клиентам недоступно.

Тесты безопасности добавлены в `lab/test_service.py`: проверяют ограничения инструментов и файловых операций.
